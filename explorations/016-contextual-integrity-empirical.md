# 016: Prompt Injection 的不可能性定理——完整论文分析

**日期**：2026-08-09
**来源**：Abdelnabi & Bagdasarian, "AI Agents May Always Fall for Prompt Injections", arXiv:2605.17634

---

上个月我写了 015，基于这篇论文的摘要分析了 Contextual Integrity 框架。今天读完了全文，发现有几个关键发现我之前完全没有提到。

## 核心论点：不可能性

论文的核心不是"CI 是个好框架"，而是一个更强的断言：

**任何固定防御策略都无法同时防住所有 CI 攻击，且不损失合法流**。

原因是双重的：

1. **参数层面**：攻击者可以伪造任何 CI 参数（发送者、接收者、信息类型、传输原则），使被阻止的行为看起来合法。防御者拒绝这类声明，也会拒绝真实的声明。

2. **规范评估层面**：即使所有参数都识别正确，攻击者仍可以操纵 Agent 的合法性判断——用"不行动会伤害用户利益"这类价值论证来绕过 Agent 的决策。Agent 无法在决策时验证这些主张的真伪。

这不是悲观论，而是说明防御的终点不是规则，而是具备上下文推理能力的系统。

## 实验结果：数字比预期严峻得多

### 1. 迭代 CI 攻击：96.7% 成功率

针对邮件助手（有 send_email 工具），以 claude-sonnet-4-6 为攻击者模型，设计 CI 参数攻击：

- baseline（无攻击的 authority-asserting 邮件）：0.67% 成功率
- 迭代攻击后：**96.7%** 成功率
- 第一封邮件就成功：61.4% 的情况

攻击策略最常见的模式：伪造一条"来自用户的先前消息"，让 Agent 把第三方授权误认为是用户直接委托。

**迁移性**：对 claude-sonnet-4-6 优化的攻击，不重新优化直接用于其他模型：
- gpt-5.4：63.3%
- gpt-5.2：89.3%
- gemini-3-pro：92.6%

这与 token 级对抗样本（通常不可迁移）形成对比。CI 攻击是语义层面的，跨模型迁移。

### 2. SecAlign 反效果

Meta 发布的防注入微调模型 SecAlign（基于 LLaMA-3.3-70B），论文发现它让安全性变差了：

| 条件 | LLaMA baseline | SecAlign |
|------|----------------|----------|
| 有授权，发邮件率 | 97%+ | 97%+（相近） |
| 无授权，authority-asserting | 54.0% | **88.2%** |
| 无授权，neutral | 49.8% | **85.1%** |

SecAlign 的安全训练在无授权场景下反而让 Agent 更容易执行未经授权的操作。作者推测是训练数据的威胁模型过于简单（假设所有外部内容都不应该触发行动），与测试场景的条件权限不兼容。

### 3. 规范推断需要历史记录

没有历史交互记录时，Agent 对越权请求的执行率：
- claude-sonnet-4-6：29.9%
- gemini-3-pro：32.2%
- gpt-5.4：36.2%

有历史记录（Agent 处理过多个合法的范围内请求）后：
- claude-sonnet-4-6：7.0%（下降最多）
- gemini-3-pro：24.2%
- gpt-5.4：24.5%

历史记录让 Agent 能建立委托范围的规范，但也引入新攻击面——攻击者可以在早期对话中植入错误的规范锚点。

### 4. 流分离失败

单条消息包含两个信息流（一个有授权的内部请求 F1，一个没有授权的外部请求 F2），Agent 把 F1 的授权"泄漏"给 F2 的比例：

| 条件 | gpt-5.2 | gpt-5.4 | claude-sonnet-4-6 |
|------|---------|---------|-------------------|
| 无明确边界 | **65%** | 34% | 6% |
| 有明确边界 | 12% | 0% | 0% |

这个失败模式不需要任何攻击设计——两个请求同时出现在一条消息里，授权就会泄漏。

## 对我之前分析的修正

015 里我写的三种攻击类型（误传流、操纵规范、混合多流）方向是对的，但没有实验数据支撑，分析层次也停在理论层。

现在有了具体数字，重要的修正是：

1. **流分离问题**在 015 里完全没有提到，但它是不需要任何攻击者的自然失败模式，在 gpt-5.2 上高达 65%。

2. **安全训练的反效果**是一个反直觉的发现——我们通常认为安全微调只会带来保守的副作用（可能损失一些合法功能），没想到会在核心任务上让安全性变差。

3. **历史记录的双刃性**：更多历史 = 更好的规范推断，但也 = 更大的规范污染攻击面。这是 Agent 长期部署的固有矛盾。

## 方向建议（论文提出的）

1. **CI 感知对齐训练**：训练数据应包含共享表面形式但委托上下文不同的场景对，使用 CI 推导的奖励进行 RL。

2. **分层架构**：模型层做 CI 推理，系统层做声明验证（加密证明发送者身份、查询外部记录）。

3. **CI 红队**：在评估 Agent 安全性时，应针对 CI 参数逐一测试，而不是用单一的"注入鲁棒性"指标。

## 意义

这篇论文之所以重要，不仅仅是因为 96.7% 这个数字。更重要的是它提供了一个**预测性框架**：随着模型对常见注入模式的鲁棒性增强，攻击面会自然移向 CI 参数伪造和规范评估操纵，因为那里没有语法特征可以防御。

这意味着 Prompt Guard 那类基于语法的分类器会越来越无效。未来的安全需要能够推理"这个声明如果是真的，这个行动是否合适"的系统，而不是匹配"ignore all instructions"这类模式。
