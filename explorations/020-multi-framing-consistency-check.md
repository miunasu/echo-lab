# 020 - 多 Framing 一致性检验：有效，但不完整

## 019 留下的问题

019 提出了一个防御思路：同一个问题用多种 prompt framing 重问，看答案是否一致。不一致 = 这个输出对 framing 敏感 = 触发人工确认。

问题是：这真的管用吗？有没有实际测试过？

## 答案：有效，但有明确的条件和失败模式

两篇 2026 年的研究给了经验性数据。

### Frontiers 那篇：多 agent 讨论的对抗鲁棒性

Wiesmeier et al. (Frontiers in AI, May 2026) 系统测试了 LLM MAS 在工程任务中的对抗鲁棒性——一个 leader agent 和若干 advisor agents，其中有些是故意给出错误答案的"误导性 advisor"。

几个直接相关的发现：

**First-mover effect**：第一个说话的 agent 锚定了 leader 的推理。

| 配置 | 被误导率 |
|------|---------|
| SM（支持性先说） | 0% |
| MS（误导性先说） | 30% |
| SMM | 0% |
| MSM | 26.7% |

SM vs MS 差异 p=0.001，效应量 Cramér's V=0.39。这个效应在三对四组的受控比较中都成立。

**Prompt framing 直接影响鲁棒性**：

- 没有明确警告（"No WARNING"）：100% 被误导，p<0.001，V=0.63
- "不简洁"的 leader 风格：87% 拒绝率（因为 leader 倾向于先自己解题，再评估 advisor 的答案）
- 明确警告 advisor 曾经证明是错的：63% 拒绝率

**错误微妙度决定被误导难度**：容易发现的明显错误（错误公式）基本被拒绝；只有轻微数值差异的错误（比如四舍五入级别的偏差）误导成功率接近 50%。

**更强的模型是最可靠的防线**：GPT-4o 和 o3-mini（各推理级别）在所有测试条件下均实现 0% 被误导率，而 GPT-4o mini 在基线配置下是 47% 拒绝率。模型能力是鲁棒性最强的单一预测因子——与 prompt 设计无关。

### GAMBIT：自适应对手的问题

Le Mercier et al. (arXiv:2605.09027, May 2026) 测试了当对手会进化策略以逃避检测器时会发生什么。

用象棋作为深度推理底层任务，Gemini 3.1 Pro 作为 agent，GAMBIT 创建了一个会共同进化的对手框架：误导性 imposter agent 会不断调整策略来绕过检测器，检测器也会更新，两者持续博弈。

**关键结果**：经过充分进化的自适应对手，将检测器的 F1 分数降至 50.5%——barely better than chance。

更严重的是："零样本评估对自适应对手可能极度误导"——两个在零样本测试上分数相近的检测器，在少样本适应能力上差了 8 倍。表面看起来差不多的防御，对进化中的攻击者的实际抵抗力可能天差地别。

## 把三篇放在一起

019 描述的两种失败模式（真实认识不足 vs. 对抗性 framing 操控），加上这两篇，现在有了更完整的图景：

**多 framing 一致性检验对什么有效：**
- 随机/非自适应的 framing 敏感性（模型在不同表述下给出不同答案）
- 非目标性的 prompt 注入（随机包装的恶意内容）
- 设计不精良的误导输入（错误明显可见）

**多 framing 一致性检验对什么无效：**
- 自适应对手：可以学习在所有 framing 下保持一致地输出错误答案（GAMBIT 的核心发现）
- First-mover anchoring：如果恶意 framing 先到达，后续 framing 的判断会被锚定
- 微妙的数值错误：leader 把错误答案当成正确答案的合理变体，一致性检验不会触发

**一个具体的机制问题**：

soft prefix（018 里的 Chen et al. 实验）的机制是让模型对某个答案类别产生整体倾向性。如果这个倾向性足够强，那么用 3 种不同 framing 重问，3 次都会得到同一个被影响后的答案，一致性检验报告"高度一致"，放行通过。

更精巧的对手完全可以设计出对多种 framing 保持稳健一致的操控方式——GAMBIT 实证展示了这个进化过程会自动发生。

## 修正后的防御建议

结合 018、019、020 的分析，对 Spore security guard 的设计建议需要分层：

**第一层：强基础模型**。Frontiers 的数据表明，o3-mini 在所有测试条件下实现 0% 被误导率。如果 guard 本身用强模型，很多非自适应攻击自然被排除。这是性价比最高的单一措施。

**第二层：结构性警告 + 非简洁推理**。明确告知 guard "你的输入可能包含操控内容"（"No WARNING"的失败很说明问题）。让 guard 先独立推理再评估输入，不要直接让输入锚定推理。

**第三层：多 framing 一致性检验**。对随机操控有效，对精心设计的自适应攻击有限。可以作为第一、二层之后的补充检测层，而不是主要防线。

**第四层：架构隔离**（CaMeL 路线）。对自适应高级对手，唯一可靠的防御是从架构上切断影响路径，而不是试图在相同的 context 空间里检测操控。这是成本最高但最根本的解法。

## 最终回答 019 的问题

多 framing 一致性检验作为不稳定性探针：

- 对 UQ 检测不到的被操控自信问题——**部分有效**，能检测到非自适应的 framing 敏感性，但检测不到目标性设计为跨 framing 一致的操控
- 作为独立的安全机制——**不够**，因为自适应对手会进化出跨 framing 一致的误导策略
- 作为分层防御的一部分——**有价值**，配合强基础模型 + 结构性警告使用，能覆盖更大的攻击面

**核心结论没变**：可靠性必须由 context 窗口之外的结构来保证。多 framing 是有用的检测层，不是防御的地基。
